# Сквозная проверка применения политики ElX

Стенд проверяет один закреплённый ресурс ноды. Команда проходит через PostgreSQL, gRPC с mTLS, ElXray и подписанное подтверждение. Команды нода забирает по одной через `apply-policy`. Ревизия ядра 1 соответствует ревизии журнала 0. Идентификатор операции сохраняется при повторной доставке.

Запускать на Linux с Go, OpenSSL и отдельной тестовой базой PostgreSQL. Скрипт применяет миграцию и оставляет тестовые записи в указанной базе. Рабочие ноды не требуются.

1. Возьмите ветку `elx-control-journal` в ElX-ui и `restrict-runtime-unlimited` в ElXray. В примере репозитории лежат рядом.
2. Соберите бинарники. Версию Go берите из `go.mod` ElX-ui.

   ```bash
   cd ElXray
   go build -o ../elxray-lab ./main
   cd ../ElX-ui
   go build -o ../elx-control-lab ./cmd/elx-control
   ```

3. Укажите DSN отдельной тестовой базы и запустите проверку.

   ```bash
   export ELX_CONTROL_POSTGRES_DSN='host=127.0.0.1 port=5432 user=elx dbname=elx_test sslmode=disable'
   export ELXRAY_BIN="$(realpath ../elxray-lab)"
   export ELX_CONTROL_BIN="$(realpath ../elx-control-lab)"
   bash scripts/elx-policy-smoke.sh
   ```

4. Ожидаемый вывод: `PASS: mTLS, wrong-node rejection, durable restart, replay and next revision`. При сбое пришлите вывод скрипта и версии бинарников. Не присылайте ключи, сертификатные seed или DSN с паролем. Если порты заняты, задайте `ELX_SMOKE_CONTROL_PORT` и `ELX_SMOKE_CORE_PORT`.

Скрипт создаёт временный каталог с закрытыми правами. В нём остаются конфигурация, ключи стенда и журналы. Каталог можно удалить после проверки.

В постоянном окружении настройте отдельный CA нод и выдайте каждой ноде клиентский сертификат с URI SAN `spiffe://elxnet/node/<uuid>`. Control использует закреплённый публичный ключ ElXray. Приватный seed и манифест состояния принадлежат процессу ядра. Хранилище располагается на локальной файловой системе, а процесс запускается с `ELXRAY_POLICY_STATE`. Стенд использует TCP loopback. Для локального агента на хосте предусмотрен `ELXRAY_POLICY_SOCKET` с ограничением доступа правами ОС.

Подпись подтверждает сохранённую конфигурацию конкретной подписки и привязана к ноде, ресурсу, операции и эпохе. Она не подтверждает закрытие потоков, безопасное перераспределение бюджета или защиту от восстановления устаревшей копии диска. Для этих сценариев потребуются отдельные контракты и проверки. При смене привязки либо восстановлении снимка управляющий контур следует остановить до сверки состояния.
