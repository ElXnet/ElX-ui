[![CI](https://github.com/ElXnet/ElX-ui/actions/workflows/ci.yml/badge.svg?branch=main)](https://github.com/ElXnet/ElX-ui/actions/workflows/ci.yml)

[![Лицензия GPL-3.0](https://img.shields.io/badge/license-GPL--3.0-blue)](LICENSE)

**ElX-ui** — административная панель, веб-интерфейс личного кабинета и интеграционный слой VPN-платформы **ElX (ElectriumX)**. Проект основан на [3X-UI](https://github.com/MHSanaei/3x-ui), но развивается как отдельный форк с управлением подписками, устройствами и согласованными ограничениями на нескольких нодах.

> **Статус:** серверные функции и интерфейсы находятся на стадии разработки и интеграционных испытаний. Существование маршрута, теста или слитого PR само по себе не подтверждает готовность публичного платного сервиса.

## Что отличает ElX-ui от оригинального 3X-UI

Сохранены базовые возможности 3X-UI: управление Xray, входящими подключениями, пользователями, нодами, сертификатами, статистикой и подписками. **Дополнительно для ElX реализованы:**

- **Единая административная точка `/panel/elx`:** просмотр прав на подписку, устройств, занятых сессий, распределённой скорости, FUP и статуса применения политик; запросы на закрытие сессий и отзыв устройств.
- **Отдельный личный кабинет `/lk`:** регистрация по одноразовому приглашению, вход по e-mail и паролю, просмотр собственных подписок, запрос отключения своих сессий, отзыв устройства, присоединение дополнительной подписки по приглашению и создание ограниченных пользовательских правил FUP.
- **Изоляция полномочий:** административная авторизация панели не подменяет авторизацию ЛК; управление требует подтверждённого владения подпиской и CSRF-проверки. Одна только ссылка подписки **не** даёт доступ к настройкам, устройствам и оплате.
- **Адаптер к отдельному ElX Control:** запросы к Control выполняются по защищённому локальному HTTP/Unix-сокету; в репозитории **нет** встроенной копии его PostgreSQL-схемы, журнала, агентов или бизнес-логики.
- **Выдача оплаченного профиля:** worker `internal/web/job/elx_profile_job.go` обрабатывает durable outbox, создаёт сначала **отключённый** VLESS-профиль на разрешённых inbound и включает его лишь после согласованных проверок Control и состояния нод.
- **Интеграционные проверки:** тесты маршрутов и разграничения API, ЛК, PostgreSQL, межнодовой синхронизации, frontend и отдельный CI-контур интеграции с Control.

Задачи ядра (исполнение скорости, подписанные подтверждения, запрет и завершение VLESS-потоков) находятся в [ElXray](https://github.com/ElXnet/ElXray), а долговременные права, FUP, журнал и межнодовая оркестрация — в [ElX-control](https://github.com/ElXnet/ElX-control). **ElX-ui не заменяет эти службы.**

## Архитектура

```text
           Администратор                 Пользователь
           /panel/elx                      /lk
                 \                         /
                  \                       /
                     ElX-ui / 3X-UI
                    (панель + frontend)
                             │
              защищённый HTTP / Unix socket
                             │
                        ElX Control
                  (PostgreSQL / права / FUP)
                       mTLS / журнал
                       /           \
                  агент A          агент B
                    │                │
                ElXray A         ElXray B
```

В обычной схеме 3X-UI управляет конфигурацией Xray и синхронизацией нод, а ElX Control отдельно управляет подписанными ограничениями и состояниями доступа. Одного `config_dirty=false` недостаточно для независимого криптографического доказательства, что конкретный профиль уже установлен в каждом ElXray.

## Разработка и проверки

**Требования:** Go из [go.mod](go.mod), Node.js/npm из [frontend/package.json](frontend/package.json); для полной интеграции — отдельные рабочие копии всех трёх репозиториев, WSL и Docker/PostgreSQL.

```bash
# Backend
go test ./internal/web/...

# Frontend
cd frontend
npm ci
npm run typecheck
npm test
npm run build
```

Полный общий прогон выполняется из `ElX-control/scripts/run-elx-windows.ps1` с параметром `-Full`; см. [план технической приёмки](https://github.com/ElXnet/ElX-control/blob/main/docs/elx/technical-acceptance-2026-11-07.ru.md). Он фиксирует версии всех трёх репозиториев и включает проверку связки с реальными процессами ElXray в локальном стенде.

**Не используйте для установки ElX команды скачивания оригинального `mhsanaei/3x-ui/install.sh`:** они устанавливают upstream 3X-UI и не обеспечивают развёртывание ElX Control и требуемого форка ядра. Сначала требуется отдельная проверенная инструкция развёртывания всей системы.

## Состояние работ и ограничения

- В `main` объединены [PR #1](https://github.com/ElXnet/ElX-ui/pull/1) и [PR #2](https://github.com/ElXnet/ElX-ui/pull/2): административный интерфейс, ЛК, интеграция Control, согласование ветки и исправления CI. [PR #3](https://github.com/ElXnet/ElX-ui/pull/3) обновил зависимость Brotli.
- Для настоящего платного запуска ещё необходимо проверить внешнюю платёжную интеграцию, подтверждение/восстановление e-mail, сетевые ограничения на массовые попытки входа и безопасное развёртывание всех компонентов.
- **Ограничение физических устройств не подтверждено:** стандартный VLESS-ключ можно скопировать; IP и HWID не являются надёжным доказательством идентичности устройства.
- Реальные Windows TUN, DNS/IPv6, мобильные сети, длительная нагрузка и аварии на VPS требуют отдельной приёмки. Интерфейсы не должны заявлять «готово» до подтверждения исходных данных и подписанных доказательств.
- Актуальные настройки, права сокетов, сертификаты и секреты не размещайте в публичных репозиториях. API Control нельзя открывать напрямую через публичный reverse proxy.
